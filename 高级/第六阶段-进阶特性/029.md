# 029. 手势系统、Gesture Arena 与命中测试

Flutter 的手势系统建立在命中测试（Hit Testing）与事件竞争机制（Gesture Arena）之上，为跨平台交互提供了一致的抽象。本节将拆解底层流程，并构建一个自定义手势案例。

## 事件传递总览

1. **Pointer 事件**：原生平台事件（触摸、鼠标、触控笔）首先被封装为 `PointerDownEvent`、`PointerMoveEvent` 等。
2. **命中测试 (HitTest)**：事件沿着渲染树自上而下传播，记录所有命中的 `RenderObject`。命中顺序由层级、`hitTest` 重写逻辑以及 `HitTestBehavior` 决定。
3. **GestureBinding**：命中的 `GestureRecognizer` 会被注册进对应的 `GestureArena`，等待竞争结果。
4. **Gesture Arena**：多个识别器对同一指针事件进行竞争，直到有一个胜出或全部失败。
5. **手势回调**：获胜的识别器触发 `onTap`、`onPanUpdate` 等高层回调。

理解这一流程有助于我们设计复杂组件的交互策略，如列表中的滑动删除、画布的多指缩放等。

## Gesture Arena 工作机制

- 每个指针（pointer）在按下时会创建一个 `GestureArena`。
- 所有命中的 `GestureRecognizer` 会通过 `GestureArenaManager` 注册到此 Arena。
- 识别器在分析事件序列后可以调用：
  - `resolve(GestureDisposition.accepted)` 表示胜出；
  - `resolve(GestureDisposition.rejected)` 表示放弃；
  - 如果所有识别器都 `rejected`，事件会回落到更基础的指针监听。
- 一旦某个识别器被接受，其他竞争者都会被强制拒绝，防止重复触发。

常见的识别器包括 `TapGestureRecognizer`、`PanGestureRecognizer`、`LongPressGestureRecognizer` 等，`GestureDetector` 其实是对这些识别器的封装。

## 命中测试技巧

- `Listener` 可以提前拦截原始指针事件，适用于自定义绘制区域。
- `IgnorePointer` 与 `AbsorbPointer` 控制命中测试的穿透与拦截。
- `HitTestBehavior.translucent` 允许命中测试穿透但仍可收到事件，常用于透明区域。

## 案例：自定义轨迹绘制手势

下面我们实现一个可在画布上绘制多段线条的组件，支持手势竞争，并利用 `RawGestureDetector` 注册自定义识别器。

```dart
import 'package:flutter/gestures.dart';
import 'package:flutter/material.dart';

class SketchPad extends StatefulWidget {
  const SketchPad({super.key});

  @override
  State<SketchPad> createState() => _SketchPadState();
}

class _SketchPadState extends State<SketchPad> {
  final _points = <Offset>[];
  late final SketchPanGestureRecognizer _recognizer;

  @override
  void initState() {
    super.initState();
    _recognizer = SketchPanGestureRecognizer()
      ..onStart = _handleStart
      ..onUpdate = _handleUpdate
      ..onEnd = _handleEnd;
  }

  void _handleStart(Offset position) {
    setState(() => _points
      ..add(position)
      ..add(position));
  }

  void _handleUpdate(Offset position) {
    setState(() => _points.add(position));
  }

  void _handleEnd() {
    setState(() => _points.add(Offset.infinite));
  }

  @override
  Widget build(BuildContext context) {
    return RawGestureDetector(
      gestures: <Type, GestureRecognizerFactory>{
        SketchPanGestureRecognizer: GestureRecognizerFactoryWithHandlers<
            SketchPanGestureRecognizer>(
          () => SketchPanGestureRecognizer(),
          (recognizer) {
            recognizer
              ..onStart = _handleStart
              ..onUpdate = _handleUpdate
              ..onEnd = _handleEnd;
          },
        ),
      },
      child: CustomPaint(
        size: Size.infinite,
        painter: _SketchPainter(points: _points),
      ),
    );
  }

  @override
  void dispose() {
    _recognizer.dispose();
    super.dispose();
  }
}

class SketchPanGestureRecognizer extends PanGestureRecognizer {
  VoidCallback? onEnd;
  ValueChanged<Offset>? onStart;
  ValueChanged<Offset>? onUpdate;

  @override
  void addAllowedPointer(PointerDownEvent event) {
    super.addAllowedPointer(event); // 交给 Gesture Arena 竞争
  }

  @override
  void handleEvent(PointerEvent event) {
    super.handleEvent(event);
    if (event is PointerDownEvent) {
      onStart?.call(event.localPosition);
    } else if (event is PointerMoveEvent && event.buttons != 0) {
      onUpdate?.call(event.localPosition);
    }
  }

  @override
  void didStopTrackingLastPointer(int pointer) {
    onEnd?.call();
    super.didStopTrackingLastPointer(pointer);
  }
}

class _SketchPainter extends CustomPainter {
  _SketchPainter({required this.points});

  final List<Offset> points;

  @override
  void paint(Canvas canvas, Size size) {
    final paint = Paint()
      ..color = Colors.orange
      ..strokeWidth = 4
      ..strokeCap = StrokeCap.round
      ..style = PaintingStyle.stroke;

    for (var i = 0; i < points.length - 1; i++) {
      final p1 = points[i];
      final p2 = points[i + 1];
      if (p1 == Offset.infinite || p2 == Offset.infinite) continue;
      canvas.drawLine(p1, p2, paint);
    }
  }

  @override
  bool shouldRepaint(covariant _SketchPainter oldDelegate) {
    return oldDelegate.points != points;
  }
}
```

### 案例亮点

- 使用 `RawGestureDetector` 直接注册 `GestureRecognizer`，可以更灵活地控制生命周期与命中策略。
- 将每次抬起事件标记为 `Offset.infinite`，用于分隔多段线条。
- `PanGestureRecognizer` 自动处理速度估计，可进一步结合动画或惯性滑动效果。

## 与内置手势的协作

- 如需阻止父组件（例如 `ListView`）抢夺手势，可以在自定义识别器中适时 `resolve(GestureDisposition.accepted)`。
- 多指手势可以通过设置 `supportedDevices` 或检测 `PointerEvent` 的 `kind`、`buttons` 实现差异化逻辑。
- 自定义组件同时支持鼠标与触控时，要注意 `PointerScrollEvent`、`PointerHoverEvent` 等额外事件类型。

掌握手势系统的底层机制，不仅有助于构建复杂交互，也为调试手势冲突提供了理论依据。结合前几节的动画与绘制知识，可以打造流畅、丰富并具有沉浸感的用户体验。
