# 024. SQLite/sqflite 深入与本地缓存案例

SQLite 是移动端常用的嵌入式关系型数据库，Flutter 社区中主要通过 `sqflite` 插件访问。掌握其表结构设计、事务处理与缓存策略，能够显著提升应用的数据可靠性。

## 为什么选择 SQLite/sqflite

- **跨平台**：安卓与 iOS 均内置 SQLite 引擎，`sqflite` 提供统一的 Dart API。
- **结构化查询**：支持复杂的 SQL 查询、索引、约束，适合关系型数据。
- **数据量级**：可轻松处理数万级别数据，远超 SharedPreferences/Hive 的轻量定位。
- **离线能力**：结合远程同步策略，可实现完整的离线优先体验。

## 表结构设计原则

1. **明确主键**：每张表需有主键（自增 ID 或业务唯一值）以支持增量更新。
2. **字段类型**：SQLite 提供 `INTEGER`、`REAL`、`TEXT`、`BLOB`、`NULL` 五类存储类，注意 Dart 与 SQLite 的类型映射。
3. **索引**：对高频查询条件建立索引，避免全表扫描。
4. **范式与反范式**：以第三范式为基础，根据业务对读性能的要求适当冗余。
5. **版本管理**：数据库升级需在 `onUpgrade` 中编写迁移脚本，确保旧数据平滑迁移。

示例表结构（文章缓存）：

```sql
CREATE TABLE article(
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  content TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  synced_at INTEGER,
  is_favorite INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX idx_article_updated_at ON article(updated_at);
```

## 使用 sqflite 管理数据库

```dart
import 'package:path/path.dart';
import 'package:sqflite/sqflite.dart';

class AppDatabase {
  AppDatabase._();
  static final AppDatabase instance = AppDatabase._();

  Database? _db;

  Future<void> init() async {
    if (_db != null) return;

    final databasesPath = await getDatabasesPath();
    final path = join(databasesPath, 'app_cache.db');

    _db = await openDatabase(
      path,
      version: 2,
      onCreate: (db, version) async {
        await db.execute('''
          CREATE TABLE article(
            id INTEGER PRIMARY KEY,
            title TEXT NOT NULL,
            content TEXT NOT NULL,
            updated_at INTEGER NOT NULL,
            synced_at INTEGER,
            is_favorite INTEGER NOT NULL DEFAULT 0
          );
        ''');
      },
      onUpgrade: (db, oldVersion, newVersion) async {
        if (oldVersion < 2) {
          await db.execute('ALTER TABLE article ADD COLUMN is_favorite INTEGER NOT NULL DEFAULT 0');
        }
      },
    );
  }

  Database get db => _db!;
}
```

- `getDatabasesPath()` 返回平台默认数据库目录。
- 通过 `onUpgrade` 有序执行迁移，避免因字段缺失导致应用崩溃。

## CRUD 与 DAO 封装

```dart
class ArticleDao {
  ArticleDao(this._db);
  final Database _db;

  Future<void> upsert(Article article) async {
    await _db.insert(
      'article',
      article.toJson(),
      conflictAlgorithm: ConflictAlgorithm.replace,
    );
  }

  Future<List<Article>> list({int limit = 20, int offset = 0}) async {
    final maps = await _db.query(
      'article',
      orderBy: 'updated_at DESC',
      limit: limit,
      offset: offset,
    );
    return maps.map(Article.fromJson).toList();
  }

  Future<void> delete(int id) => _db.delete(
        'article',
        where: 'id = ?',
        whereArgs: [id],
      );
}

class Article {
  Article({
    required this.id,
    required this.title,
    required this.content,
    required this.updatedAt,
    this.syncedAt,
    this.isFavorite = false,
  });

  final int id;
  final String title;
  final String content;
  final DateTime updatedAt;
  final DateTime? syncedAt;
  final bool isFavorite;

  Map<String, dynamic> toJson() => {
        'id': id,
        'title': title,
        'content': content,
        'updated_at': updatedAt.millisecondsSinceEpoch,
        'synced_at': syncedAt?.millisecondsSinceEpoch,
        'is_favorite': isFavorite ? 1 : 0,
      };

  static Article fromJson(Map<String, dynamic> json) => Article(
        id: json['id'] as int,
        title: json['title'] as String,
        content: json['content'] as String,
        updatedAt: DateTime.fromMillisecondsSinceEpoch(json['updated_at'] as int),
        syncedAt: json['synced_at'] == null
            ? null
            : DateTime.fromMillisecondsSinceEpoch(json['synced_at'] as int),
        isFavorite: (json['is_favorite'] as int) == 1,
      );
}
```

- 使用 `ConflictAlgorithm.replace` 可实现 UPSERT（存在则覆盖）。
- DateTime 字段转换为 Unix 时间戳存储，避免时区问题。

## 事务处理与批量操作

事务用于保证多条 SQL 的原子性，典型场景包括批量插入、同步与级联更新。

```dart
Future<void> syncArticles(List<Article> articles) async {
  final db = AppDatabase.instance.db;
  await db.transaction((txn) async {
    final batch = txn.batch();
    for (final article in articles) {
      batch.insert(
        'article',
        article.toJson(),
        conflictAlgorithm: ConflictAlgorithm.replace,
      );
    }
    await batch.commit(noResult: true);

    await txn.update(
      'article',
      {'synced_at': DateTime.now().millisecondsSinceEpoch},
      where: 'id IN (${articles.map((_) => '?').join(',')})',
      whereArgs: articles.map((a) => a.id).toList(),
    );
  });
}
```

- `transaction` 遇到异常会自动回滚，确保数据一致。
- `Batch` 提供批量执行能力，减少与数据库的往返次数。

## 构建本地缓存案例：离线文章阅读

目标：实现一个“远程 + 本地”的缓存层，保障离线浏览体验。

1. **数据层分工**：
   - **RemoteDataSource**：调用后端 API，返回最新文章列表。
   - **LocalDataSource (SQLite)**：保存文章正文、更新时间戳、收藏标记等信息。
   - **Repository**：组合远程与本地数据，提供统一接口给上层。

2. **缓存策略**：
   - 首次加载：优先返回本地缓存，让 UI 先展示旧数据。
   - 同时发起远程请求，若成功则刷新缓存并通知 UI。
   - 若远程失败，则保留本地数据并展示错误提示。

```dart
class ArticleRepository {
  ArticleRepository(this._remote, this._local);

  final RemoteDataSource _remote;
  final ArticleDao _local;

  Stream<List<Article>> watchArticles() async* {
    yield await _local.list();

    try {
      final remoteArticles = await _remote.fetchArticles();
      await _local.db.transaction((txn) async {
        final batch = txn.batch();
        for (final article in remoteArticles) {
          batch.insert(
            'article',
            article.toJson(),
            conflictAlgorithm: ConflictAlgorithm.replace,
          );
        }
        await batch.commit(noResult: true);
      });
      yield await _local.list();
    } catch (error) {
      // 可以记录日志或上报监控
      rethrow;
    }
  }
}
```

3. **同步标记**：
   - 利用 `updated_at` 与 `synced_at` 字段判断是否需要向服务器推送本地变更。
   - 本地编辑后，将记录标记为“待同步”，在网络可用时统一提交。

4. **缓存清理**：定时或在存储超限时删除过期数据，保持数据库体积可控。

## 性能与稳定性建议

- 打开数据库连接后全局复用，避免频繁打开/关闭造成性能损耗。
- 对关键操作加上超时与异常捕获，防止 UI 卡顿。
- 结合 `moor/drift` 等 ORM 可获得更高层次的类型安全，但也要权衡学习成本与灵活性。
- 测试迁移脚本：升级应用时模拟旧版本数据库，确保迁移逻辑覆盖所有历史版本。
