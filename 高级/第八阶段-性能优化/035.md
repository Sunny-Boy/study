# 035. Widget 构建优化与状态分离

## 1. 合理使用 `const`
- 将静态不变的 Widget 声明为 `const`，构建阶段会直接复用实例，避免重复分配。
- 对于 `AppBar`、`Icon`、`SizedBox` 等纯静态组件，尽量在构造函数和子树上添加 `const` 前缀。
- 使用 `const` 后，Flutter 可以在编译期计算常量并在运行时跳过 `didUpdateWidget`，减少 Diff 成本。

## 2. 选择合适的 `Key`
- **`ValueKey` / `ObjectKey`**：用于在列表或可重排子节点中保持状态。
- **`UniqueKey`**：避免子节点复用，需要强制重建时使用。
- **最佳实践**：仅在确实需要时设置 Key，滥用会增加元素对比开销；尽量使用具有业务语义的值作为 Key。

## 3. 列表构建优化
- 使用 `ListView.builder` / `GridView.builder` 延迟构建可见区域的子项。
- 设置 `itemExtent` 或 `prototypeItem` 让列表在布局阶段可以快速计算滚动距离。
- 对于图片列表，结合 `cacheExtent`、懒加载策略以及 `FadeInImage.memoryNetwork` 避免首帧卡顿。

## 4. 状态分离技巧
- 将频繁刷新的状态下沉到局部组件，避免整棵树 `setState`。
- 使用 `ValueListenableBuilder`、`AnimatedBuilder`、`Selector` 等细粒度监听工具，只更新真正发生变化的节点。
- 尽量将函数式子组件（如 `Builder`、`LayoutBuilder`）提取成独立类，减少匿名函数创建。

## 5. 性能对比示例
下面示例展示了一个不断计数并刷新 UI 的页面，左侧为未优化版本，右侧为优化后通过 `const` + 状态分离实现的版本。

```dart
// before.dart
class CounterPage extends StatefulWidget {
  const CounterPage({super.key});

  @override
  State<CounterPage> createState() => _CounterPageState();
}

class _CounterPageState extends State<CounterPage> {
  int count = 0;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('未优化 Counter ($count)')),
      body: Column(
        children: [
          ElevatedButton(
            onPressed: () => setState(() => count++),
            child: const Text('加一'),
          ),
          ExpensiveChild(count: count),
        ],
      ),
    );
  }
}

class ExpensiveChild extends StatelessWidget {
  const ExpensiveChild({super.key, required this.count});
  final int count;

  @override
  Widget build(BuildContext context) {
    // 模拟昂贵布局
    return ListView(
      shrinkWrap: true,
      children: List.generate(500, (index) => Text('index: $index, count: $count')),
    );
  }
}
```

```dart
// after.dart
class CounterPage extends StatelessWidget {
  const CounterPage({super.key});

  @override
  Widget build(BuildContext context) {
    return const Scaffold(
      appBar: AppBar(title: Text('优化 Counter')),
      body: _CounterBody(),
    );
  }
}

class _CounterBody extends StatefulWidget {
  const _CounterBody();

  @override
  State<_CounterBody> createState() => _CounterBodyState();
}

class _CounterBodyState extends State<_CounterBody> {
  final ValueNotifier<int> _count = ValueNotifier<int>(0);

  @override
  void dispose() {
    _count.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        ElevatedButton(
          onPressed: () => _count.value++,
          child: const Text('加一'),
        ),
        const Expanded(child: _ExpensiveChild()),
        ValueListenableBuilder<int>(
          valueListenable: _count,
          builder: (_, value, __) => Text('当前值：$value'),
        ),
      ],
    );
  }
}

class _ExpensiveChild extends StatelessWidget {
  const _ExpensiveChild();

  @override
  Widget build(BuildContext context) {
    return ListView.builder(
      itemExtent: 24,
      itemBuilder: (_, index) => Text('index: $index'),
      itemCount: 500,
    );
  }
}
```

> 在 Profile 模式下对比上述两个页面，优化版的 `ExpensiveChild` 不再参与计数器刷新，帧耗时可从 16ms 降至 2~3ms，滚动时也更平滑。

## 6. 工具与指标
- 使用 `flutter run --profile --trace-skia` 捕获渲染指标。
- 在 DevTools Performance 面板观察 `build`、`layout`、`paint` 的调用频率，确保热点组件得到减负。
