# 034. 性能分析工具总览

## 1. Flutter DevTools
- **启动方式**：在终端执行 `flutter pub global run devtools` 或通过 `flutter run` 后在命令行提示中打开 DevTools 链接。
- **功能模块**：包括 Performance、Memory、CPU Profiler、Network 等多个面板，可用于实时观察应用运行时的资源使用情况。
- **Profile 目标**：锁定掉帧、Jank、内存飙升等异常，并结合日志定位到具体的 Widget、Dart 方法或 Engine 任务。

## 2. Timeline (Performance 面板)
- **Frame Chart**：展示每一帧的 UI / Raster / GPU 线程耗时，常见的红色框代表掉帧。
- **Timeline Events**：记录 Dart 代码、引擎任务、平台线程的执行片段，可在火焰图中查找慢操作。
- **Raster Stats**：带有图像解码、层合成等耗时统计，用于判断是否存在大规模重绘。

## 3. Profile 模式
- **运行命令**：`flutter run --profile` 或 `flutter attach --profile`，在 Profile 模式下保留优化的 JIT，同时还能采集实时性能数据。
- **适用场景**：接近真实发布环境（Release）的性能表现，适合查找运行时瓶颈；比 `--debug` 少了调试开销。
- **注意事项**：Profile 模式默认禁用 Hot Reload，可使用 Hot Restart；确保真机连接获取更真实的 CPU / GPU 数据。

## 4. 采集性能数据的流程示例
1. 使用真机运行 `flutter run --profile`，启动 DevTools Performance 面板。
2. 点击 `Record` 按钮开始录制，执行你希望分析的用户操作（如滚动、动画或网络请求）。
3. 停止录制，观察 Frame Chart 中是否有红色的长条（表示掉帧）。
4. 在 Timeline Events 中定位到耗时的任务，查看其关联的 Widget 构建或方法调用。
5. 切换到 Memory 面板，确认是否存在内存暴涨或频繁 GC。

## 5. 导出与共享数据
- DevTools 支持下载 `.json` 格式的 Timeline 记录，可在团队内共享问题现场。
- 使用 `flutter screenshot --observatory-uri=<uri>` 可截取性能叠加层（Performance Overlay）进行对比。
- 对于 CI 场景，可使用 `flutter drive --trace-startup --profile` 自动采集关键性能指标。
