## 项目实践要点

### 1. 代码规范
- 遵循 Dart 官方代码风格
- 使用有意义的命名（变量、函数、类）
- 添加必要的注释（特别是复杂逻辑）
- 保持代码简洁，避免过度嵌套

### 2. 项目结构
推荐按功能模块组织：
```
lib/
├── core/          # 核心工具、常量
├── data/          # 数据层（模型、仓库）
├── business_logic/ # 业务逻辑层（Bloc/Cubit）
└── presentation/  # 展示层（页面、组件）
```

### 3. 状态管理选择
| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| 简单应用 | Provider | 学习成本低，易上手 |
| 中型应用 | Bloc/Cubit | 清晰的事件驱动模型 |
| 大型应用 | Riverpod | 更好的类型安全与可测试性 |

### 4. 性能优化原则
- 使用 `const` 构造函数减少重建
- 列表使用 `.builder` 构造器
- 图片启用缓存与压缩
- 避免在 `build` 方法中执行耗时操作
- 合理使用 `Consumer` 限制重建范围

### 5. 测试建议
- **单元测试**：覆盖核心业务逻辑（目标 >70%）
- **Widget 测试**：验证 UI 组件行为
- **集成测试**：测试关键用户流程
- **性能测试**：使用 DevTools 分析性能瓶颈

## 常见问题与解决方案

### Q1: 如何选择状态管理方案？
**A:** 根据项目复杂度选择：
- 简单页面 → `setState`
- 跨组件共享 → `Provider`
- 复杂业务逻辑 → `Bloc`
- 追求类型安全 → `Riverpod`

### Q2: 网络请求失败如何处理？
**A:** 建立分层错误处理机制：
1. 网络层：封装统一的异常类型
2. 仓库层：捕获并转换错误
3. UI 层：根据错误类型展示友好提示
4. 关键操作：添加重试机制

### Q3: 如何优化应用启动速度？
**A:** 多个优化点：
- 延迟加载非关键模块
- 减少启动时的网络请求
- 使用 `isolate` 处理耗时初始化
- 优化图片资源大小
- 启用 Dart AOT 编译

### Q4: 发布前需要检查什么？
**A:** 使用发布检查清单：
- [ ] 所有功能测试通过
- [ ] 修复已知 Bug
- [ ] 性能达标（无明显卡顿）
- [ ] 准备应用图标和启动页
- [ ] 隐私政策和用户协议
- [ ] 应用商店素材（截图、描述）
