# 036. 绘制与内存优化策略

## 1. 控制重绘：`RepaintBoundary`
- 将频繁重绘的区域包裹在 `RepaintBoundary` 中，隔离无关子树，避免父层级被迫重绘。
- 常见场景：复杂动画组件、实时图表、视频播放。当 `shouldRepaint` 为 `true` 时，只重绘边界内的内容。
- 使用 DevTools 的 `Repaint Rainbow`（勾选 Performance Overlay）可以直观查看哪些区域发生重复绘制。

```dart
RepaintBoundary(
  child: CustomPaint(
    painter: WavePainter(progress: value),
  ),
)
```

## 2. 合理管理 Layer
- **避免深层次透明度**：将 `Opacity` 用在静态子树上会触发额外的 `saveLayer`，可用 `FadeTransition` 等组合动画替代。
- **使用 `Transform` / `Clip` 的开销**：大型裁剪与复杂变换会生成新的 Layer，应尽量合并或放置在根部。
- **Layer 调试**：DevTools "Render Layers" 面板可查看当前帧的 Layer 树，重点关注是否存在大量空层或重复层。

## 3. 图片内存优化
- 为大图指定 `cacheWidth` / `cacheHeight`，在加载阶段按需缩放。
- 使用 `ResizeImage` 或 `flutter_image_compress` 对动态图片做体积压缩。
- 通过 `precacheImage` 控制缓存，避免一次性加载过多图片导致内存抖动。
- 对动图（GIF/APNG）考虑使用 `video_player` 或 Lottie 以降低 CPU 解码压力。

## 4. 帧率分析示例
1. 在终端执行 `flutter run --profile --trace-skia` 并打开 DevTools Performance。
2. 勾选 `Show Performance Overlay`，观察 UI / Raster 线程的帧耗时柱状图。
3. 如果 UI 线程柱状图高于 16ms，表示存在构建或布局瓶颈；Raster 线程高于 16ms 则可能是绘制、合成或图片解码导致。
4. 在 Timeline 中展开 `Raster Thread`，定位到耗时的 `Picture` 或 `Layer`。
5. 分别应用 `RepaintBoundary`、图片压缩等优化后再次采集数据，对比帧耗时变化。

> 实践技巧：在帧率分析时，保持测试场景稳定（例如滚动同一列表 30 秒），采集多次结果以排除偶发抖动的影响。

## 5. 内存监控
- DevTools Memory 面板提供堆快照和 GC 统计，重点关注 `Dart Heap` 持续增长的情况。
- 使用 `profile_memory` 包或 `vm_service` API 可在代码中定期记录内存指标。
- 当发现图片缓存占用过高时，可调用 `imageCache.clear()` 或设定 `maximumSizeBytes` 控制上限。
