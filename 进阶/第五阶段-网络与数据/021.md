# 021. HTTP 请求流程与 Flutter 网络库对比

## HTTP 请求的完整生命周期

1. **域名解析（DNS Lookup）**：客户端根据请求的域名向 DNS 服务器发起查询，获取目标服务器的 IP 地址。
2. **TCP/TLS 连接建立**：
   - 对于 HTTP：通过三次握手建立 TCP 连接。
   - 对于 HTTPS：在 TCP 之上额外进行 TLS 握手协商密钥，确保通信加密。
3. **构建请求报文**：客户端组合请求行（方法、URL、协议版本）、请求头（Header）以及可选的请求体（Body）。
4. **服务器处理请求**：服务器解析报文、执行业务逻辑、访问数据库或调用其他服务，并生成响应。
5. **返回响应报文**：响应包含状态行（状态码、原因短语）、响应头和响应体；客户端根据需要解析正文（JSON/HTML/二进制等）。
6. **连接复用与关闭**：HTTP/1.1 默认启用 keep-alive 以复用连接；HTTP/2 在单个 TCP 连接上复用多条流；若启用 HTTP/3 则基于 QUIC 传输。

> **提示**：定位网络异常时，可以沿着上述流程逐步排查：DNS 是否解析成功、TLS 是否握手失败、请求是否携带了必要的 Header、服务器业务是否正常返回等。

## HTTP 报文结构与常用概念

- **方法（Method）**：`GET` 用于查询、`POST` 用于提交、`PUT/PATCH` 用于更新、`DELETE` 用于删除，还包括 `HEAD`、`OPTIONS` 等方法。
- **状态码（Status Code）**：2xx 表示成功，3xx 代表重定向，4xx 为客户端错误，5xx 为服务器错误。
- **Headers**：在请求和响应中传递元信息，如认证 Token、缓存控制、内容类型等。
- **幂等性**：`GET`、`PUT`、`DELETE` 天生幂等，`POST` 非幂等；设计接口时需要考虑重试策略与数据一致性。

## Flutter 网络请求库对比：`http` vs `dio`

| 对比维度 | `http` 包 | `dio` 包 |
| --- | --- | --- |
| 定位 | Dart 官方维护，定位为轻量级 HTTP 客户端 | 社区维护的功能型 HTTP 框架 |
| API 风格 | 函数式：`http.get(...)` / `http.post(...)` | 面向对象：`dio.get(...)`，支持实例级配置 |
| 拦截器 | 不支持 | 支持请求/响应/错误拦截器，可统一处理 Token、日志、重试 |
| 取消请求 | 需手动管理 `Client` | 内置 `CancelToken`，可随时中断请求 |
| FormData/文件上传 | 需手动拼装 | 内置 `FormData`、文件分片、进度回调 |
| 自定义配置 | 通过构造 `Client` 手动配置 | `BaseOptions` 集中配置超时、Header、BaseUrl 等 |
| 生态扩展 | 基础功能，需自行封装 | 丰富的插件（缓存、重试、日志等）与社区封装 |

**选型建议**：
- 只需简单请求或在命令行/服务端环境中，`http` 足够。
- 需要全局拦截、复杂配置、文件上传或统一错误处理时，优先选择 `dio`。

## 使用 `http` 包的 GET / POST 实战

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

class PostApi {
  final http.Client _client;

  PostApi({http.Client? client}) : _client = client ?? http.Client();

  Future<List<Post>> fetchPosts() async {
    final response = await _client.get(
      Uri.parse('https://jsonplaceholder.typicode.com/posts'),
      headers: {
        'Accept': 'application/json',
      },
    );

    if (response.statusCode != 200) {
      throw HttpException('load posts failed: ${response.statusCode}');
    }

    final List<dynamic> jsonList = jsonDecode(response.body) as List<dynamic>;
    return jsonList.map((json) => Post.fromJson(json as Map<String, dynamic>)).toList();
  }

  Future<Post> createPost({required String title, required String content}) async {
    final response = await _client.post(
      Uri.parse('https://jsonplaceholder.typicode.com/posts'),
      headers: {
        'Content-Type': 'application/json',
      },
      body: jsonEncode({
        'title': title,
        'body': content,
        'userId': 1,
      }),
    );

    if (response.statusCode != 201) {
      throw HttpException('create post failed: ${response.statusCode}');
    }

    return Post.fromJson(jsonDecode(response.body) as Map<String, dynamic>);
  }
}

class Post {
  final int id;
  final String title;
  final String body;

  const Post({required this.id, required this.title, required this.body});

  factory Post.fromJson(Map<String, dynamic> json) => Post(
        id: json['id'] as int,
        title: json['title'] as String,
        body: json['body'] as String,
      );
}

class HttpException implements Exception {
  final String message;
  HttpException(this.message);

  @override
  String toString() => message;
}
```

- `http.Client` 建议在合适的生命周期内复用，避免频繁创建；在不需要时调用 `close()` 释放资源。
- 通过 `jsonDecode` 解析响应体，配合模型对象可避免后续出现动态类型错误。

## 使用 `dio` 包的 GET / POST 实战

```dart
import 'package:dio/dio.dart';

class PostService {
  final Dio _dio;

  PostService({Dio? dio})
      : _dio = dio ??
            Dio(BaseOptions(
              baseUrl: 'https://jsonplaceholder.typicode.com',
              connectTimeout: const Duration(seconds: 5),
              receiveTimeout: const Duration(seconds: 8),
              headers: {'Accept': 'application/json'},
            ))
          ..interceptors.add(LogInterceptor(responseBody: true));

  Future<List<dynamic>> fetchPosts() async {
    final response = await _dio.get('/posts');
    return response.data as List<dynamic>;
  }

  Future<Map<String, dynamic>> createPost({
    required String title,
    required String content,
  }) async {
    final response = await _dio.post(
      '/posts',
      data: {
        'title': title,
        'body': content,
        'userId': 1,
      },
      options: Options(
        contentType: Headers.jsonContentType,
      ),
    );

    return response.data as Map<String, dynamic>;
  }

  Future<void> uploadAttachment(String filePath) async {
    final formData = FormData.fromMap({
      'file': await MultipartFile.fromFile(filePath),
    });

    await _dio.post('/attachments', data: formData);
  }
}
```

- `BaseOptions` 集中配置 Base URL、超时与通用 Header，简化多接口调用。
- `LogInterceptor` 有助于开发期排查请求参数与响应数据。
- `DioError` 包含丰富的错误类型（超时、取消、服务器错误等），可用于精细化的错误处理与重试策略。

## 优化网络请求的实践建议

- **缓存策略**：对于读操作频繁且数据更新不敏感的接口，可结合本地缓存（如 SharedPreferences、Hive、SQLite）减少网络请求次数。
- **错误重试与退避**：对网络波动敏感的请求，可实现指数退避（exponential backoff），在 `dio` 中可通过拦截器实现。
- **安全性**：HTTPS 为默认选择，必要时开启证书固定（Pinning）；敏感数据加密传输，避免通过 URL Query 暴露。
- **监控与日志**：记录关键请求的响应时间、状态码、错误信息，为线上问题定位提供依据。
