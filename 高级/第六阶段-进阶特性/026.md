# 026. Flutter 动画体系与隐式动画

Flutter 的动画系统由渲染树、调度器与动画库协同工作，能够在每一帧对组件属性进行平滑插值。理解这个体系的关键在于弄清楚动画帧是如何被驱动、状态又是如何回调到 widget 上的。

## 动画体系核心概念

1. **SchedulerBinding / Ticker**：Flutter 内部的 `SchedulerBinding` 会以屏幕刷新率（默认 60 FPS）触发 frame 回调。`Ticker` 对象以回调的形式将这一节奏暴露给开发者，是动画驱动的起点。
2. **Animation**：代表一个随时间变化的值，通常是 `Animation<double>`。它提供 `value`、`status`、`addListener` 等方法，用来监听数值或状态的变化。
3. **AnimationController**：在需要显式控制动画时使用，能够启动、停止、反转动画，并定义动画持续时长。它本质上是带有 `Ticker` 的动画源。
4. **Tween & CurvedAnimation**：`Tween` 负责把 0~1 的动画进度映射到具体数值，`CurvedAnimation` 则负责非线性节奏的插值。

在隐式动画中，我们无需手动管理 `Ticker`，Flutter 会在内部替我们创建和释放；理解这些底层角色有助于在出现性能或状态问题时快速定位。

## Ticker 与 Animation 的协作

- **TickerProvider**：为了避免重复创建 `Ticker`，Flutter 通过 `TickerProvider`（如 `SingleTickerProviderStateMixin`）来统一管理。隐式动画内部也会实现 `TickerProviderStateMixin`，确保在组件移除时自动 `dispose`。
- **帧回调流程**：`Ticker` 每帧调用监听器，`Animation` 根据当前时间计算出新的 `value`，进而请求 `setState` 触发重建，最终由渲染树在 `paint` 阶段输出新的像素。

了解这套流程能帮助我们诊断掉帧、重建频繁等问题。例如在动画过程中执行昂贵的同步操作，就可能阻塞下一帧渲染。

## 隐式动画简介

隐式动画（Implicit Animations）通过在 widget 属性发生变化时自动过渡到新值，极大降低了使用门槛。常见的隐式动画组件包括：

- `AnimatedContainer`
- `AnimatedOpacity`
- `AnimatedAlign`
- `AnimatedDefaultTextStyle`
- 等等……

它们通常遵循以下模式：

```dart
AnimatedWidget(
  duration: const Duration(milliseconds: 300),
  curve: Curves.easeInOut,
  // 传入的属性发生变化时自动过渡
)
```

与显式动画相比，隐式动画更适合简单的状态过渡场景，如按钮按下的渐变、列表项的尺寸变化等。

## 示例：AnimatedContainer 实现隐式过渡

下面的示例展示了如何通过 `AnimatedContainer` 在颜色与尺寸变化时自动播放动画：

```dart
import 'dart:math';
import 'package:flutter/material.dart';

class ImplicitAnimationDemo extends StatefulWidget {
  const ImplicitAnimationDemo({super.key});

  @override
  State<ImplicitAnimationDemo> createState() => _ImplicitAnimationDemoState();
}

class _ImplicitAnimationDemoState extends State<ImplicitAnimationDemo> {
  double _size = 120;
  Color _color = Colors.blue;
  BorderRadiusGeometry _borderRadius = BorderRadius.circular(24);

  void _randomize() {
    final random = Random();
    setState(() {
      _size = 80 + random.nextInt(120).toDouble();
      _color = Color.fromRGBO(
        random.nextInt(256),
        random.nextInt(256),
        random.nextInt(256),
        1,
      );
      _borderRadius = BorderRadius.circular(random.nextInt(60).toDouble());
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('隐式动画示例')),
      body: Center(
        child: AnimatedContainer(
          width: _size,
          height: _size,
          decoration: BoxDecoration(
            color: _color,
            borderRadius: _borderRadius,
          ),
          duration: const Duration(milliseconds: 350),
          curve: Curves.easeInOut,
        ),
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _randomize,
        child: const Icon(Icons.play_arrow),
      ),
    );
  }
}
```

### 示例解析

- 当 `_size`、`_color`、`_borderRadius` 的值发生变化时，`AnimatedContainer` 会在 350 ms 内自动插值到新数值。
- `curve` 控制了动画节奏，`Curves.easeInOut` 先慢后快再慢，感觉更自然。
- 无需显式管理 `Ticker` 或 `AnimationController`，组件内部会对生命周期进行处理。

### 使用建议

- 隐式动画适合状态驱动视图的细粒度过渡，能显著提升交互反馈。
- 当动画依赖用户手势实时驱动或需要多阶段串联时，应该转向显式动画方案。
- 频繁 rebuild 的父组件可能导致隐式动画被意外重置，可以通过抽离 widget 或使用 `AnimatedSwitcher` 减少影响。
