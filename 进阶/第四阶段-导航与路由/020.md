# 020. Navigator 2.0、Router API 与现代路由管理

随着多端融合、深度链接和状态同步需求的增加，Navigator 1.0 的命令式模型逐渐暴露出局限。Navigator 2.0 提供了以 **声明式 Router API** 为核心的导航体系，允许开发者用应用状态驱动页面栈，并与 URL、平台返回键、浏览器历史等保持一致。

## Navigator 1.0 vs 2.0

| 对比项 | Navigator 1.0 | Navigator 2.0 |
| --- | --- | --- |
| 架构风格 | 命令式：直接调用 `push/pop` | 声明式：依据状态定义页面列表 |
| 深度链接 | 需手动解析 `onGenerateRoute` | 内建支持 `RouteInformation` 同步 |
| 浏览器地址栏 | 需自定义处理 | 与 `RouteInformationParser` 协同自动同步 |
| 导航历史 | Navigator 自己维护 | 开发者管理一个可序列化的导航状态 |
| 场景 | 中小规模、线性流程 | 大型应用、Web、桌面、多终端 |

## Router API 核心组件

1. **RouteInformationProvider**：提供原始路由信息（通常来自浏览器地址栏）。
2. **RouteInformationParser**：解析字符串路由信息为应用可理解的数据模型。
3. **RouterDelegate**：根据当前 app 状态构建页面栈（`Navigator.pages`）。
4. **BackButtonDispatcher**：统一处理系统返回事件，实现 Web/Android/iOS 一致的回退行为。

> Navigator 2.0 中仍然复用 `Navigator` 组件，但更多时候通过 `Navigator.pages` 提供 `Page` 列表，由框架负责 diff 与动画。

## 最小可用示例：基于状态的页面栈

```dart
class AppRoutePath {
  const AppRoutePath.home() : isDetails = false, itemId = null;
  const AppRoutePath.details(this.itemId) : isDetails = true;

  final bool isDetails;
  final int? itemId;
}

class AppRouterDelegate extends RouterDelegate<AppRoutePath>
    with ChangeNotifier, PopNavigatorRouterDelegateMixin<AppRoutePath> {
  AppRouterDelegate();

  final GlobalKey<NavigatorState> navigatorKey = GlobalKey<NavigatorState>();
  AppRoutePath _currentPath = const AppRoutePath.home();

  AppRoutePath get currentConfiguration => _currentPath;

  @override
  Widget build(BuildContext context) {
    return Navigator(
      key: navigatorKey,
      pages: [
        MaterialPage(
          key: const ValueKey('HomePage'),
          child: HomeScreen(onSelect: _handleSelect),
        ),
        if (_currentPath.isDetails)
          MaterialPage(
            key: ValueKey('Details-${_currentPath.itemId}'),
            child: DetailScreen(
              itemId: _currentPath.itemId!,
              onPop: _handlePop,
            ),
          ),
      ],
      onPopPage: (route, result) {
        if (!route.didPop(result)) {
          return false;
        }
        _handlePop();
        return true;
      },
    );
  }

  void _handleSelect(int id) {
    _currentPath = AppRoutePath.details(id);
    notifyListeners();
  }

  void _handlePop() {
    _currentPath = const AppRoutePath.home();
    notifyListeners();
  }

  @override
  Future<void> setNewRoutePath(AppRoutePath configuration) async {
    _currentPath = configuration;
  }
}

class AppRouteInformationParser extends RouteInformationParser<AppRoutePath> {
  @override
  Future<AppRoutePath> parseRouteInformation(RouteInformation routeInformation) async {
    final uri = Uri.parse(routeInformation.location ?? '/');
    if (uri.pathSegments.isNotEmpty && uri.pathSegments.first == 'detail') {
      final id = int.tryParse(uri.pathSegments.elementAt(1));
      if (id != null) {
        return AppRoutePath.details(id);
      }
    }
    return const AppRoutePath.home();
  }
}
```

应用入口：

```dart
class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  final delegate = AppRouterDelegate();
  final parser = AppRouteInformationParser();

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      routerDelegate: delegate,
      routeInformationParser: parser,
      backButtonDispatcher: RootBackButtonDispatcher(),
    );
  }
}
```

### 导航状态同步案例解析
- 当用户点击首页条目时，`_handleSelect` 更新 `_currentPath`，`notifyListeners` 触发 Router 重新构建页面栈。
- `Navigator.pages` 自动 diff 出需要新增的详情页，并更新浏览器地址为 `/detail/:id`。
- 用户点击浏览器返回键或调用 `Navigator.pop` 时触发 `onPopPage`，回调 `_handlePop`，同步状态回到首页。
- 通过 `setNewRoutePath` 支持外部（URL）→ 内部（状态）的同步，适配深度链接。

## 现代路由库：GoRouter 概览

为了简化 Navigator 2.0 的模板代码，Flutter 团队推出了官方推荐的 `go_router` 库。它封装了 Router API，提供声明式路由表、重定向、守卫等能力。

```dart
final GoRouter router = GoRouter(
  initialLocation: '/',
  routes: [
    GoRoute(
      path: '/',
      builder: (_, __) => const HomeScreen(),
      routes: [
        GoRoute(
          path: 'detail/:id',
          builder: (_, state) => DetailScreen(itemId: int.parse(state.params['id']!)),
        ),
      ],
    ),
  ],
  redirect: (context, state) {
    final isLoggedIn = context.read<AuthBloc>().state.isLoggedIn;
    final loggingIn = state.subloc == '/login';
    if (!isLoggedIn && !loggingIn) return '/login';
    if (isLoggedIn && loggingIn) return '/';
    return null;
  },
);

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp.router(
      routerConfig: router,
    );
  }
}
```

### 声明式路由的优势
1. **状态驱动**：URL、导航栈、UI 都由同一个状态源驱动，便于测试与调试。
2. **深链友好**：支持浏览器刷新、直接打开任意路径，轻松对接外部链接。
3. **可组合**：GoRouter、Beamer、AutoRoute 等库提供模块化路由、嵌套路由、导航守卫等高级特性。

### 何时仍使用 Navigator 1.0？
- 应用页面数量少，导航路径简单。
- 不关注浏览器地址栏、外部深链。
- 团队偏好命令式调用，迭代周期短。

## 导航策略选择建议
- **混合方案**：多数现代库仍可访问底层 `Navigator`。当需要临时弹出对话框或底部菜单时，可继续调用 `context.push`、`Navigator.of(context).push` 等 API。
- **模块化拆分**：对大型应用，可将某个子模块使用 GoRouter 或 AutoRoute 管理，外层通过 `ShellRoute` 或独立 RouterDelegate 对接，实现渐进式迁移。
- **状态同步**：在使用状态管理（Bloc、Riverpod、Provider）时，将路由状态纳入统一的状态树，可实现 "URL ←→ 状态 ←→ UI" 的三向同步，提升可观测性与可测试性。

## 小结
Navigator 2.0 通过声明式 Router API 让导航状态成为一等公民，为 Web、桌面和深度链接场景提供了统一答案。借助 GoRouter 等现代库，可以在保持高可维护性的同时快速构建复杂的导航体验。在实际项目中，可根据业务复杂度选择从 Navigator 1.0 逐步演进到 2.0，或直接引入更高层的路由框架来提高生产力。
