# 022. JSON 解析、模型封装与 `json_serializable`

JSON 是客户端与服务端通信最常见的数据格式。掌握其解析方式、模型封装策略与自动化序列化工具，能够让数据层代码既安全又易于维护。

## JSON 基础回顾

- **数据结构**：支持字符串、数字、布尔值、`null`、数组与对象（键值对）。
- **编码与解码**：在 Dart 中通过 `dart:convert` 的 `jsonEncode` 与 `jsonDecode` 完成；解码结果通常是 `Map<String, dynamic>` 或 `List<dynamic>`。
- **类型安全挑战**：直接操作 `dynamic` 易引发运行时错误，需要模型层对数据进行约束。

## 手动解析与模型封装

```dart
import 'dart:convert';

class User {
  final int id;
  final String name;
  final String email;

  const User({required this.id, required this.name, required this.email});

  factory User.fromJson(Map<String, dynamic> json) => User(
        id: json['id'] as int,
        name: json['name'] as String,
        email: json['email'] as String,
      );

  Map<String, dynamic> toJson() => {
        'id': id,
        'name': name,
        'email': email,
      };
}

void main() {
  const jsonStr = '{"id":1,"name":"Alice","email":"alice@example.com"}';
  final Map<String, dynamic> jsonMap = jsonDecode(jsonStr) as Map<String, dynamic>;
  final user = User.fromJson(jsonMap);
  print(user.name);
}
```

手动写 `fromJson`/`toJson` 可以完全掌控序列化逻辑，但随着模型增多，重复代码和维护成本迅速上升。

## 使用 `json_serializable` 自动生成模型代码

`json_serializable` 通过静态代码生成的方式为模型自动生成 `fromJson`/`toJson`，是 Flutter 社区最常用的序列化方案。

### 1. 添加依赖

```yaml
dependencies:
  json_annotation: ^4.8.0

dev_dependencies:
  build_runner: ^2.4.0
  json_serializable: ^6.7.0
```

### 2. 定义模型

```dart
import 'package:json_annotation/json_annotation.dart';

part 'user.g.dart';

@JsonSerializable()
class User {
  final int id;
  final String name;
  final String email;
  final DateTime? birthday;

  const User({
    required this.id,
    required this.name,
    required this.email,
    this.birthday,
  });

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);

  Map<String, dynamic> toJson() => _$UserToJson(this);
}
```

- `@JsonSerializable()` 启用注解处理。
- `part 'user.g.dart';` 指向将要生成的文件。
- 可通过注解参数定制字段映射，如 `@JsonKey(name: 'user_id')`、`@JsonKey(defaultValue: [])`。

### 3. 运行代码生成

```bash
flutter pub run build_runner build --delete-conflicting-outputs
```

该命令扫描注解，利用源代码生成器生成 `user.g.dart`：

```dart
User _$UserFromJson(Map<String, dynamic> json) => User(
      id: json['id'] as int,
      name: json['name'] as String,
      email: json['email'] as String,
      birthday: json['birthday'] == null
          ? null
          : DateTime.parse(json['birthday'] as String),
    );

Map<String, dynamic> _$UserToJson(User instance) => <String, dynamic>{
      'id': instance.id,
      'name': instance.name,
      'email': instance.email,
      'birthday': instance.birthday?.toIso8601String(),
    };
```

### 4. 集成到项目中

- 建议将模型放置在 `lib/models` 或 `lib/data/models` 目录，保持结构清晰。
- 对于需要转换为非标准格式的字段，可以使用 `fromJson`/`toJson` 回调：

```dart
@JsonKey(fromJson: _fromTimestamp, toJson: _toTimestamp)
final DateTime createdAt;

static DateTime _fromTimestamp(int value) => DateTime.fromMillisecondsSinceEpoch(value);
static int _toTimestamp(DateTime dateTime) => dateTime.millisecondsSinceEpoch;
```

## 底层序列化机制解析

`json_serializable` 基于 Dart 的 **源代码生成（Source Generation）**：

1. Build Runner 执行时读取 Dart 源码的 AST（抽象语法树）。
2. `json_serializable` 分析每个带注解的类，生成对应的序列化函数。
3. 最终输出的 `_$.g.dart` 文件在编译期直接参与编译，无需运行时反射。

与 Java/Kotlin 的反射方式相比，代码生成的优势在于：
- **零运行时开销**：无需反射或 `mirror`，性能更好，编译体积更小。
- **编译期安全**：字段名、类型错误能够在生成阶段被发现。
- **树摇优化友好**：不依赖运行时反射，`dart2js`、`Dart AOT` 均可轻松裁剪无用代码。

## 进阶建议

- 将原始 JSON 模型与业务领域模型分离，便于不同数据源复用。
- 搭配 `freezed` 等数据类生成工具，可获得不变性、拷贝方法与模式匹配能力。
- 对第三方或动态结构的 JSON，可先通过 `json_serializable` 生成基础模型，再手动扩展自定义逻辑（如校验与转换）。
