# 018. Navigator 1.0 基础与路由栈原理

Navigator 1.0 是 Flutter 诞生之初就存在的命令式导航系统，它把路由（Route）按照先进后出的栈（Stack）结构管理。开发者通过显式调用 `push`、`pop` 等方法来改变路由栈，进而切换页面。

## 路由栈的工作方式
- Navigator 内部维护一个 `List<Route<dynamic>>`，顶部（top）元素代表当前展示的页面。
- 调用 `Navigator.push` 会将新的 `Route` 入栈，现有页面在栈中被覆盖但仍保留状态。
- 调用 `Navigator.pop` 会让顶部 Route 出栈，回到前一个页面；如果没有上一个 Route，`pop` 的行为由 `onPopPage` 或平台返回键控制。
- Route 通常由 `MaterialPageRoute` 或 `CupertinoPageRoute` 等具体实现封装，它们决定了转场动画与视觉风格。

> **小提示：** Navigator 1.0 通过命令式 API 控制路由栈，因此非常适合简单应用与传统多页面开发场景。

## 常用 API

### `Navigator.push`
- 签名：`Future<T?> push<T extends Object?>(BuildContext context, Route<T> route)`
- 作用：将 Route 入栈并异步返回路由关闭时的结果。
- 常见用法：
  ```dart
  Navigator.of(context).push(
    MaterialPageRoute(builder: (_) => const DetailPage()),
  );
  ```

### `Navigator.pop`
- 签名：`bool pop<T extends Object?>(BuildContext context, [ T? result ])`
- 作用：将顶部 Route 出栈，可携带返回值；返回 `true` 表示成功出栈。
- 结合 `popUntil` 可批量回退到指定页面。

### 其他辅助方法
- `pushReplacement`：用新 Route 替换当前顶部 Route。
- `pushAndRemoveUntil`：入栈后移除满足条件之前的所有 Route，用于重置导航历史。
- `maybePop` / `canPop`：在尝试出栈前判断是否存在上级路由。

## 案例：从列表跳转详情并返回结果

```dart
class ArticleListPage extends StatelessWidget {
  const ArticleListPage({super.key});

  @override
  Widget build(BuildContext context) {
    final articles = List.generate(3, (i) => '文章 $i');

    return Scaffold(
      appBar: AppBar(title: const Text('文章列表')),
      body: ListView.builder(
        itemCount: articles.length,
        itemBuilder: (_, index) {
          return ListTile(
            title: Text(articles[index]),
            onTap: () async {
              final liked = await Navigator.of(context).push<bool>(
                MaterialPageRoute(
                  builder: (_) => ArticleDetailPage(title: articles[index]),
                ),
              );

              if (liked == true && context.mounted) {
                ScaffoldMessenger.of(context).showSnackBar(
                  SnackBar(content: Text('${articles[index]} 已收藏')),
                );
              }
            },
          );
        },
      ),
    );
  }
}

class ArticleDetailPage extends StatelessWidget {
  const ArticleDetailPage({super.key, required this.title});

  final String title;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text(title)),
      body: Center(
        child: ElevatedButton(
          onPressed: () => Navigator.of(context).pop(true),
          child: const Text('收藏并返回'),
        ),
      ),
    );
  }
}
```

### 案例解析
1. 列表页面通过 `push` 打开详情页面，并 `await` 返回值。
2. 详情页在执行收藏操作后通过 `pop(true)` 返回并携带状态。
3. 列表页收到结果后根据业务需求刷新提示，实现了路由栈的闭环交互。

## 使用建议
- 页面之间存在明显的前后层级关系时，优先使用 Navigator 1.0，易于维护。
- 注意在 `async` 回调中判断 `context.mounted`，避免在页面已销毁时调用 `Navigator`。
- 当需要管理复杂返回路径时，结合 `popUntil` 与自定义 `RoutePredicate` 可以让路由栈更可控。
