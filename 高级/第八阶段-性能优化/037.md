# 037. 启动速度与包体积优化

## 1. 启动速度优化
- **预热与延迟初始化**：在 `main()` 中尽量少做同步阻塞操作，使用 `WidgetsFlutterBinding.ensureInitialized()` 后再执行异步初始化。
- **分阶段渲染**：分离启动页与主页面，使用轻量级 `SplashScreen`，待必要数据加载完成后再过渡到主界面。
- **追踪启动耗时**：执行 `flutter run --profile --trace-startup`，在日志中获取 `timeToFirstFrame` 与 `timeToFirstFrameRasterized`。
- **预编译 Shader**：使用 `flutter build bundle --bundle-sksl-path shaders.sksl.json`，避免首帧因 Shader 编译造成卡顿。

## 2. 包体积优化
- **资源拆分**：将大体积图片、视频放在 CDN 或按需下载，Flutter 端只保留关键资源。
- **按 ABI 拆分**：Android 使用 `flutter build apk --split-per-abi`，可将 APK 从 ~50MB 降到 20MB 左右。
- **压缩与瘦身**：移除未使用的字体、L10n 文案，开启 `--tree-shake-icons` 清理冗余矢量图标。

## 3. 延迟加载策略
- 使用 `deferred` 导入：
  ```dart
  import 'package:feature/feature.dart' deferred as feature;

  Future<void> _loadFeature() async {
    await feature.loadLibrary();
    feature.run();
  }
  ```
- 对首页不需要立即展示的模块，通过路由懒加载或 `FutureBuilder` 延迟创建。
- 利用 `Isolate` 或后台任务预加载数据，但注意与主线程通信成本。

## 4. 代码混淆与符号表
- Android：在 `android/app/build.gradle` 中启用 `minifyEnabled true`，配合 `proguard-rules.pro` 保留 Flutter 引擎和插件需要的类：
  ```gradle
  buildTypes {
      release {
          signingConfig signingConfigs.release
          minifyEnabled true
          shrinkResources true
          proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
      }
  }
  ```
- iOS：在 Xcode 的 `Build Settings` 中开启 `LLVM -> Other C Flags` 混淆或使用第三方脚本，确保符号表上传 App Store。
- Dart 层：发布时可以执行 `flutter build apk --obfuscate --split-debug-info=build/debug_info`，保留调试符号以便崩溃分析。

## 5. 构建命令示例
```bash
# Android 发布版（按 ABI 拆分 + 混淆 + 缩减资源）
flutter build apk \
  --release \
  --split-per-abi \
  --obfuscate \
  --tree-shake-icons \
  --split-debug-info=build/debug_info

# iOS 发布版（生成 IPA 并输出体积分析报告）
flutter build ipa --obfuscate --tree-shake-icons --export-options-plist=ios/ExportOptions.plist

# 分析包体积构成
flutter build appbundle --release --analyze-size
```

## 6. 配置清单检查
- 核对 `AndroidManifest.xml` 是否启用 `android:extractNativeLibs="false"`，减少解压成本。
- 在 iOS `Info.plist` 中关闭未使用的权限声明，避免额外审核及二进制冗余。
- 保持第三方插件精简，定期排查未使用的依赖并移除。

> 将启动速度、包体积指标纳入发布流程（如在 CI 中记录耗时、大小），能持续监控回归并指导后续优化。
